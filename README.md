# Neon Dev / CyberPulse site

Одностраничный сайт студии/разработчика для продажи сайтов бизнесу: промо-страницы, лендинги и небольшие многостраничные сайты. Проект собран на React + Vite + Tailwind CSS, с дополнительными статическими файлами в `public` и PHP-обработчиком формы для хостинга.

Этот README описывает проект без папки `dist`. `dist` считается результатом сборки и не используется как источник правок.

## Быстрый старт

```bash
npm install
npm run dev
npm run check
npm run build
```

- `npm run dev` запускает локальную разработку через Vite.
- `npm run check` проверяет `public/custom.js`, `public/contact.php` и собирает проект.
- `npm run build` создает готовую версию в `dist`.
- `npm run preview` показывает уже собранную версию.

## Стек

- React 19, точка входа: `src/main.jsx`.
- Vite 7, конфиг: `vite.config.js`.
- Tailwind CSS 4 через `@tailwindcss/vite`.
- Framer Motion для анимаций.
- Lucide React для иконок.
- PHP `mail()` для отправки заявок: `public/contact.php`.
- Яндекс.Метрика подключена в `index.html`, счетчик: `109145693`.

## Как работает главная страница

`index.html` задает базовую SEO-обвязку:

- `<html lang="ru">`
- `<title>` и meta description
- `robots: index, follow`
- canonical на `https://neon-dev.ru/`
- Open Graph и Twitter Card
- favicon
- Google Fonts
- Яндекс.Метрика
- подключение `/src/main.jsx`, `/custom.css`, `/custom.js`

React-приложение собирается из `src/App.jsx`:

- `Header` - фиксированная навигация, мобильное меню.
- `Hero` - первый экран с оффером.
- `Services` - тарифы из `pricingTiers`.
- `Portfolio` - карточки работ из `portfolio`.
- `ProjectModal` - полноэкранная модалка проекта.
- `Workflow` - процесс работы из `workflow`.
- `Terms` - условия оплаты, возврата и правок.
- `Footer` - старый футер/контакт, который затем удаляется `public/custom.js`.
- `BackToTop` - кнопка возврата наверх.

Важно: `public/custom.js` после загрузки страницы удаляет React-футер `footer#contact` и добавляет новую секцию `section.sales-contact` с формой, live-проектами, футером, cookie-баннером и плавающей кнопкой обсуждения проекта. Поэтому контактная зона фактически управляется не `App.jsx`, а `public/custom.js` + `public/custom.css`.

## Формы и заявки

На сайте есть две формы:

- основная форма в секции `sales-contact`;
- быстрая форма в `.quick-modal`.

Обе создаются в `public/custom.js` и отправляют POST на `/contact.php`.

Обязательные поля:

- `name`
- `contact`
- `message`
- `personal_data_agree=yes`
- `privacy_read=yes`

Служебные поля:

- `plan`
- `price`
- `consent_version`
- `privacy_version`

После успешной отправки вызывается цель Яндекс.Метрики `lead_sent`. При клике по тарифу вызывается `tariff_click`.

## SEO-состояние на сейчас

Что уже есть:

- главная индексируемая;
- title и description на главной;
- canonical на `https://neon-dev.ru/`;
- Open Graph / Twitter preview;
- `robots.txt`;
- `sitemap.xml`;
- 404 с `noindex, follow`;
- юридические страницы с `noindex, follow`;
- изображения портфолио имеют `alt` в React-карточках;
- базовая структура заголовков есть, но ее нужно проверить после финальных SEO-правок.

Что стоит поправить первым:

- `public/robots.txt`: сейчас sitemap указан как `https://neon-dev.ru//sitemap.xml`, надо убрать двойной слеш.
- `public/sitemap.xml`: сейчас `http://neon-dev.ru/` и старый `lastmod`; лучше поставить `https://neon-dev.ru/` и актуальную дату.
- Проверить, нужен ли бренд `CyberPulse`, `CYBER`, `NEON DEV` в одном стиле. Сейчас в проекте встречаются разные названия.
- Проверить H1/H2 после рендера: в React есть основной H1, а в модалке проекта тоже используется H1, но модалка открывается только интерактивно.
- Добавить JSON-LD разметку для `LocalBusiness` или `ProfessionalService`, `WebSite`, `Service`, возможно `OfferCatalog`.
- Проверить, не мешает ли динамическая вставка контактной секции индексации важных коммерческих текстов. Для SEO-критичных блоков лучше держать контент в исходном HTML/React, а не только добавлять через JS.
- Сжать изображения в `public/img`: сейчас PNG-файлы довольно крупные, можно сделать WebP/AVIF и оставить fallback.
- Добавить явные width/height или стабильные aspect-ratio для важных изображений, чтобы снизить CLS.
- Проверить текст оффера под целевые запросы: "разработка сайтов для бизнеса", "создание лендинга", "сайт под ключ", "разработка сайта компании".

## SEO-правки: где начинать

1. Техническая база: `robots.txt`, `sitemap.xml`, canonical, Open Graph, HTTPS, 404.
2. Семантика главной: title, description, H1, H2, тексты тарифов и контактного блока.
3. Структурированные данные: JSON-LD в `index.html`.
4. Скорость: оптимизация изображений, проверка лишнего JS, метрики Lighthouse.
5. Индексация коммерческого контента: решить, какие важные блоки должны быть в React-разметке сразу, а какие могут оставаться в `custom.js`.

## Для проработки конверсии

Первый набор правок для трафика из Директа:

- Бренд в шапке должен быть `NEON DEV`, без ощущения, что пользователь попал просто в портфолио.
- Главная кнопка на первом экране ведет к консультации/заявке, а переход к процессу работы остается второстепенным.
- Цена `от 45 000 ₽` показывается на первом экране и рядом с формой, потому что это сильный фильтр и аргумент.
- Оффер должен быть конкретным: сайт под ключ, срок, чистый код, без конструкторов, аналитика и заявки.
- Форма должна быть короткой: имя + контакт, детали задачи уточняются в переписке.
- Согласия объединяются в один видимый чекбокс, при этом ссылки на согласие и политику остаются.
- Кнопка отправки должна быть видна без лишней прокрутки, особенно на мобильном.

Следующие гипотезы для теста:

- Проверить CTA-текст: `Получить консультацию`, `Обсудить проект`, `Узнать стоимость`.
- Сделать отдельный первый экран под рекламу: "Лендинг для бизнеса от 45 000 ₽".
- Добавить рядом с CTA короткие гарантии: фикс бюджета, запуск на хостинг, аналитика, адаптив.
- Добавить мини-блок доверия до тарифов: 3-4 факта о процессе и результате.
- Проверить, какой контакт конвертит лучше: форма, Telegram, звонок.

## Деплой на Beget

Перед деплоем задаются переменные окружения:

```bash
export BEGET_HOST="ssh.beget.com"
export BEGET_USER="login"
export BEGET_PATH="/home/login/neon-dev.ru/public_html"
npm run deploy:beget
```

`scripts/deploy-beget.sh` запускает `npm run check`, собирает `dist` и отправляет только содержимое `dist/` на сервер через `rsync`.

## Важные замечания для будущих правок

- Не править `dist` вручную: все изменения должны идти через `src`, `public`, `index.html` и затем сборку.
- `public/assets/index-8EiOxp41.js` выглядит как старый/собранный артефакт. Его лучше не трогать, если текущая версия собирается из `src`.
- В проекте есть `importmap` в `index.html`, но при Vite-сборке зависимости обычно идут из npm. Перед крупной чисткой стоит проверить, нужен ли importmap в production.
- При изменении формы не забывать синхронизировать фронтенд-поля в `public/custom.js` и проверки в `public/contact.php`.
- При изменении юридических документов обновлять скрытые версии `consent_version` и `privacy_version` в формах.
